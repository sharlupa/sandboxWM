# sandboxWM

[English version](./README_EN.md)

**sandboxWM** — экспериментальный Wayland-композитор на Rust: обычный BSP/Dwindle-тайлинг на лету превращается в физическую песочницу. Окна падают, сталкиваются и вращаются. Курсором можно рисовать полки, клей, батуты и верёвки, скреплять окна сваркой, пружиной или верёвкой, мять окна как желе и резать их ножом на части. При выходе всё это сохраняется.

> ⚠️ **Статус: 0.2.0, экспериментальный.** Все пункты [концепта](./sandboxWM_concept.md) реализованы, но проект молодой: ждите шероховатостей, особенно с экзотическими клиентами.

**Разработка с помощью ИИ:** проект и его концепция разрабатываются при участии нейросетей (AI coding assistants).

## Концепт → реализация

| Пункт концепта | Статус | Как устроено |
|---|---|---|
| §1 Бесконечный холст, гравитация, пол | ✅ | rapier2d, окна — динамические тела, пол на нижнем краю экрана, камера с зумом к курсору |
| §1 Режим 1: обычная гравитация | ✅ | `Super+1` |
| §1 Режим 2: окна плавно встают в тайлинг | ✅ | `Super+2` / `Super+G`, анимированный переход в обе стороны; при возврате окна встают на прежние места |
| §1 Режим 3: невесомость одного окна | ✅ | `Super+3`, тело становится кинематическим: висит, его не продавить, но можно тащить и крутить |
| §1 Режим 4: невесомость для всех | ✅ | `Super+4` |
| §2 Рисование линий: сталь, клей, батут, верёвка | ✅ | `Super+P`; цепочки капсул-коллайдеров, верёвка — цепь звеньев на шарнирах |
| §2 Клей: отрывается рывком мыши | ✅ | Шов — fixed joint, рвётся при превышении `detach_force` |
| §2 Верёвка падает и болтается, на неё вешается окно | ✅ | Начало закреплено; поднеси окно мышью к свободному концу — оно зацепится |
| §3 Сохранение сессии | ✅ | Линии, связи, окна, камера и режим; автосохранение, перезапуск приложений при старте |
| §4 Сварка, пружина, верёвка между окнами | ✅ | `Super+E/S/R`, затем клик по двум окнам; верёвка проходит сквозь связанные окна |
| §5 Мягкие окна (желе, вытягивание, сплющивание) | ✅ | `Super+J`, `Super+Shift+ЛКМ`; сетка PBD + mesh-шейдер поверх снимка окна |
| §6 Обратное проецирование ввода | ✅ | Клики и выделение текста проходят через поворот, масштаб, разрез и деформацию сетки |
| §7 Слайсинг окна ножом | ✅ | `Super+X`, провести поперёк окна; части — кадры одного буфера, приложение работает целиком |

Кроме концепта: XWayland (Steam, Discord и другие X11-клиенты), DMA-BUF, wlr-screencopy (OBS через xdg-desktop-portal-wlr), wlr-output-management (только чтение), буфер обмена и primary selection, `wp_viewporter`, серверные декорации, VT-переключение, рендер по требованию.

## Управление

Все сочетания — с `Super`. Клавиши настраиваются в `[controls]`.

### Общее

| Клавиша | Действие |
|---|---|
| `Super+Enter` | Терминал (по умолчанию `kitty`) |
| `Super+W` | Закрыть активное окно |
| `Super+Q` / `Super+Esc` | Выйти из WM (сессия сохраняется) |
| `Super+G` | Тайлинг ↔ физика (плавно) |
| `Super+Стрелки` | Тайлинг: фокус на соседнее окно в этом направлении; физика: двигать камеру |
| `Super+ЛКМ` + тянуть | Тайлинг: менять пропорции тайлов; физика: тащить окно за точку захвата (с раскачкой и броском) |
| `ЛКМ` | Фокус и обычная работа с окном |
| `Ctrl+Alt+F1…F12` | Переключить VT (TTY/DRM) |
| `Super+F5` | Сохранить сессию сейчас |

### Физика и камера

| Клавиша | Действие |
|---|---|
| `Super+1` | Режим 1: обычная гравитация (включает физику) |
| `Super+2` | Режим 2: гравитация выключена, окна плавно встают в тайлинг |
| `Super+3` | Режим 3: невесомость активного окна (переключатель) |
| `Super+4` | Режим 4: невесомость для всех (переключатель) |
| `Super+A` / `Super+D` | Удерживать — крутить активное окно |
| `Super+колесо`, `Super+-` / `Super+=` | Зум камеры к курсору |
| `Super+0` | Сбросить камеру |
| `Super+C` | Собрать все разбросанные окна в кадр: сеткой на полу, камера подстраивается |
| Средняя кнопка + тянуть | Панорама камеры |

### Инструменты

| Клавиша | Действие |
|---|---|
| `Super+P` | Рисование линий. `ЛКМ` — рисовать, `ПКМ` — стереть линию под курсором, `1`–`4` или `Tab` — сталь/клей/батут/верёвка, `Delete` — стереть все линии, `Esc` — выход |
| `Super+X` | Нож: провести `ЛКМ` поперёк окна. Горизонтальный штрих режет по горизонтали, вертикальный — по вертикали |
| `Super+E` / `Super+S` / `Super+R` | Сварка / пружина / верёвка: клик по первому окну, затем по второму (точки клика — точки крепления) |
| `Super+U` | Снять с активного окна связи, клей и подвес на верёвке |
| `Super+J` | Сделать активное окно мягким ↔ жёстким |
| `Super+Shift+ЛКМ` + тянуть | Тянуть окно за край — вытянуть, смять (окно становится мягким) |
| `Super+Z` | Вернуть форму и склеить разрезанное окно |

## Сборка и запуск

Нужны Rust (edition 2024) и системные библиотеки: `libwayland`, `libxkbcommon`, `libinput`, `libudev`, `libseat`, `libgbm`, `libEGL`/`libGLESv2`, `libdrm`; для X11-приложений — `Xwayland`.

```sh
# Debian/Ubuntu
sudo apt install libudev-dev libinput-dev libseat-dev libgbm-dev libegl-dev \
    libwayland-dev libxkbcommon-dev libdrm-dev libgles-dev xwayland

cargo build --release
./target/release/sandboxWM
```

Режим выбирается автоматически: без `WAYLAND_DISPLAY` и `DISPLAY` (запуск из TTY) — нативный DRM/KMS через libseat; иначе — вложенное окно Winit внутри текущей сессии.

Тесты: `cargo test`. GL-тесты mesh-рендера используют программный EGL (Mesa llvmpipe) и пропускаются, если его нет.

## Конфигурация

Первая найденная директория: `$SANDBOXWM_CONFIG`, `$XDG_CONFIG_HOME/sandboxWM/`, `~/.config/sandboxWM/`, `./config/`. Все `*.conf` в ней — TOML, сливаются потаблично: секцию можно продолжить в другом файле, а сломанный файл пропускается с сообщением и не обнуляет остальные.

| Файл | Секции |
|---|---|
| `sandboxWM.conf` | `[physics]` (гравитация, пол, плотность, трение, зум…), `[controls]` |
| `gravity.conf` | `[gravity_modes]`: длительность перехода, невесомость |
| `drawing.conf` | `[drawing]`, `[materials.steel/glue/trampoline/rope]` |
| `joints.conf` | `[joints.weld/spring/rope]` |
| `softbody.conf` | `[soft_body]`: мягкость, сплющивание, пластичность, сетка, обратное проецирование |
| `slicing.conf` | `[slicing]` |
| `session.conf` | `[session]`: автосохранение, путь, формат TOML/JSON, перезапуск приложений |
| `window.conf` | `[window_props]` и overrides по app_id: `[window_props.apps."org.gnome.Nautilus"] weight = 2.0, softness = 0.3, floating = true` |
| `rendering.conf` | `[rendering]`: цвет фона, обводка окон (толщина, цвет обычных и активного) |

Сессия по умолчанию лежит в `$XDG_STATE_HOME/sandboxWM/session.toml` (рядом — `.bak`), лог паник — в `$XDG_STATE_HOME/sandboxWM/panic.log`.

## Как это устроено

- `src/main.rs` — запуск, выбор бэкенда, winit-цикл.
- `src/backend_drm.rs` — DRM/KMS, EGL/GBM, libinput, курсор, screencopy.
- `src/state.rs` — состояние композитора, тайлинг, фокус, Wayland-обработчики (xdg-shell, попапы с grab, буфер обмена, viewporter…).
- `src/sandbox.rs` — физическая песочница поверх состояния: куски окон, инструменты, режимы гравитации, переходы, обратное проецирование, оверлей, сессия.
- `src/physics.rs` — мир rapier2d: куски окон, линии и материалы, верёвки, связи, клей, перетаскивание, хуки контактов.
- `src/softbody.rs` — мягкое тело окна (PBD-сетка с пластичностью и инерционными псевдосилами).
- `src/render.rs` — render-элементы: повёрнутые/обрезанные куски окон, сборка кадра для обоих бэкендов.
- `src/mesh_render.rs` — снимки окон и GLES-отрисовка деформированной сетки.
- `src/overlay.rs` — линии, верёвки, связи, превью инструментов и пол одним draw call; отсечение по damage.
- `src/session.rs` — сохранение/загрузка сессии, сопоставление окон, перезапуск приложений.
- `src/cursor.rs` — курсор в DRM-режиме (клиентские поверхности, xcursor-тема, аппаратная плоскость).
- `src/tiling.rs` — BSP/Dwindle-дерево; `src/xwm.rs` — XWayland; `src/screencopy.rs`, `src/output_manager.rs` — wlr-протоколы.

Отличия от исходного технического плана концепта:
- Рендер — GLES (Smithay) с собственными шейдерами для сетки и оверлея, без отдельного wgpu/glow.
- Слайсинг режет по осям окна: каждая часть — прямоугольный кадр того же буфера, как в `wp_viewporter`. Сам протокол `wp_viewporter` тоже поддерживается для клиентов.
- X11-окна в физике не вращаются: XWayland не умеет повёрнутую геометрию, и координаты кликов Steam/CEF съезжали бы.

## Известные ограничения

- Один монитор; масштаб 1 (HiDPI-буферы рисуются уменьшенными).
- Деформированное мягкое окно рисуется по снимку и перерисовывает свой bounding box каждый кадр, пока колеблется.
- Перезапуск приложений из сессии работает для обычных процессов; сложные (Steam, CEF-обёртки, Snap после обновления) могут не подняться из своего argv.
